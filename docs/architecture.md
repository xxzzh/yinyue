# 结构与扩展

## 当前结构

- `src/data.ts`：课程、知识段落、互动类型、题目与解释。
- `src/music.ts`：Tonal 音高计算、吉他指板与和弦、音程题、拍速计算、MusicXML 谱例。
- `src/audio.ts`：按用户操作延迟加载 Tone.js，统一音量、钢琴与拨弦参考音、节拍器调度。
- `src/progress.ts`：无 UI 的进度模型、日期、活动、去重完成、连续天数与导入校验。
- `src/state.tsx`：本地持久化、统一活跃计时、提示信息；一处计时，避免课程与内嵌工具重复累计。
- `src/learning.ts`：稳定的 React Context 与 hooks，和组件导出分离以支持开发热更新。
- `src/Tools.tsx`：钢琴、吉他、听音、节拍器、视唱、乐谱等工具。
- `src/App.tsx`：页面导航、课程窗口、搜索、记录导入导出、个人学习设置。
- `src/Art.tsx`：原创 SVG 音乐插画；有配图的乐器课程改用 `InstrumentImage` 显示真实照片。
- `src/instrument-guides.ts`：每件乐器的使用说明与演奏指南链接，及排序去重规则 `playingGuides`。
- `src/CatalogPager.tsx`：各目录共用的分页器。

## 按需加载

`App.tsx` 用 `React.lazy` 按需加载中国乐器、世界乐器、选乐器页面，乐器特色区块，以及钢琴、吉他、练耳、节拍器、乐谱等工具；首屏只包含外壳、课程数据与配图数据。Tone.js 与 OpenSheetMusicDisplay 本来就在用户操作时才加载。新增页面或重型组件时沿用这种方式，避免重新并入主包。

## 代码规范

- ESLint（`npm run lint`）与 Prettier（`npm run format:check`，行宽120）在 GitHub Pages 构建中执行；`npm run format` 自动排版。生成文件 `src/instrument-images.ts`、`src/audio-samples.ts` 不参与排版。
- `react-hooks/set-state-in-effect` 与 `react-hooks/refs` 暂为警告：分页器、筛选重置、图片重载等处在 effect 中同步重置状态。后续可改为在事件处理里重置或用 `key` 重建组件，改完后再把这两条规则恢复为错误。

## 数据契约

每节课使用稳定的 `lesson.id`。更换内容来源时保留这些标识，避免已有完成记录失效。课程详情需要保存标题、分组、段落、互动类型及测验；由适配层将后台内容转换为 Course／Lesson 数据。现有构建直接使用本地类型化内容，未接入外部 API。

进度 `version: 1` 包含完成列表、目标、音量、按本地日期的实际学习秒数／完成数／练习数。导入备份时合并完成列表；同一天的计数取最大值，以避免同一份备份重复导入后膨胀。

后续账号与云同步需要一个独立服务：以已认证用户为主体保存进度，定义多设备合并与版本迁移规则，再替换本地保存层。不要把用户识别信息直接放进 URL 或前端密钥。

## 扩展顺序

1. 持续补齐与校审中文入门课程，以及实体乐器示范视频。
2. 完成 Educandu 验证后，再接内容编辑和发布流程。
3. 加入账号与云端记录，再考虑教师后台或班级。
4. 为实际 MIDI 设备做浏览器、踏板、音域与重复音验收。
5. 麦克风识别另设技术验证：单音音准、节奏、和弦属于不同问题，不能把普通音高检测直接称为完整演奏评分。

本版没有虚构登录、排行榜、学员人数、评分或已上线的教学视频。
